# 포트폴리오 보완 스프린트

[GitHub Sprint 1](https://github.com/edonghyun/ttyroom/milestone/1) · [백로그](BACKLOG.md) · [현재 작업](HANDOFF.md)

목표는 공개 소스를 재현하고, 실제 협업을 시연하고, 핵심 설계의 선택과 비용을 설명하는 것이다.
이전 MVP의 F1–F7 이후 작업을 F8부터 이어간다. 기존 MVP 기록은 과거 상태로 보존한다.

GitHub issue의 완료 기준과 상태가 기준이다. BACKLOG.md는 우선순위·의존성 안내이며
HANDOFF.md는 마지막 작업의 근거와 다음 진입점을 기록한다. 기한은 아직 정하지 않는다.

## 진행 방식

1. HANDOFF.md와 해당 issue의 완료 기준·의존성을 확인한다.
2. 한 번에 한 작업만 진행한다. 막히면 원인과 필요한 결정을 적고 완료로 표시하지 않는다.
3. 코드 변경은 [공통 가이드](../../docs/CODE_STYLE.md)와 [Java 테스트 기준](../../backend/TESTING.md)을 따른다.
4. 구현 → 관련 검증 → 리뷰·리팩터링 → 재검증을 마친 뒤 커밋과 결과를 연결한다.
5. 완료 기준을 충족했을 때 issue를 닫고 HANDOFF.md에 다음 작업을 남긴다. 테스트 실패나 남은 미구현을 숨기지 않는다.

새 기능의 RED와 특성화·동작 보존 리팩터링을 구분한다. fixture 준비와 행동, 관찰, assertion의
역할을 유지하고 테스트 순서에 의존하지 않는다. 리뷰는 패턴 이름보다 책임·불변식·실패 의미를 본다.
커밋 메시지는 변경 목적과 검증 범위를 기록하며, 로컬 로그·임시 파일은 artifacts/에 보관한다.

완료한 작업의 요약은 [WORK_LOG](../../docs/WORK_LOG.md)에 추가한다. 작업별 날짜 문서를 새로 만들지 않는다.
현재 설계·검증 결과는 각 담당 문서를 갱신하고 상세 변경은 커밋으로 연결한다.
