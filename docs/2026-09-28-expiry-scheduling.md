# 만료 예약 계약 정리 — P3z

> `artifacts/` 경로는 로컬 보관 자료이며 공개 저장소에는 포함하지 않습니다. 수치와 명령은 작성 당시의 검증 기록입니다.

2026-09-28. [품질 리뷰](2026-09-25-node-java-quality-review.md)의 타이머 상속 항목을 정리했다.
`ExpiryTimers`가 일반 실행기를 상속하던 구조를 내부 합성으로 바꾸고, 호출부에 필요한
예약·취소·종료만 남겼다. 방의 만료 정책이나 종료 순서는 변경하지 않았다.

## 호출부가 알아야 하는 계약

- `schedule(expiry, delay, unit)`은 취소 핸들을 반환한다. 작업 완료를 나타내는 Future는 아니다.
- `Cancellation.cancel()`은 아직 전달을 시작하지 않은 예약을 취소한다. 전달이 시작된 작업은
  취소와 경합해 실행될 수 있다. 작업을 중단하거나 완료를 기다리지는 않으며 반복 취소도 허용된다.
- `close()`는 미래 예약을 취소하고 전달 실행기를 닫은 다음, 전달된 만료 작업의 종료를 기다린다.
  종료 후 새 예약은 `RejectedExecutionException`으로 거절한다.
- 만료 작업은 각각 가상 스레드에서 실행한다. 한 방의 저장 대기가 다른 방의 만료 전달을 막지 않는다.

이전 `ScheduledFuture.get()`은 만료 본문이 아닌 worker 전달의 완료를 의미했다. 실제 호출부는
완료 결과를 사용하지 않았으므로, 일반 Future를 완전히 구현하는 대신 오해할 수 있는 API를 제거했다.
취소 후에도 이미 전달된 콜백은 실행될 수 있다. `RoomSessions`의 Member 동일성·연결 상태 검사는
계속 필요하며, 오래된 콜백을 직접 실행하는 재접속 회귀 테스트도 유지했다.

`RoomSessions`는 작은 구체 타입인 `ExpiryTimers`를 받는다. 별도의 scheduler 인터페이스·구현 계층은
추가하지 않았다. 기존 수동 만료 fixture는 이 타입과 취소 핸들을 대역으로 사용한다. 실제 실행기와
예약 큐, 가상 스레드 수명 관리는 `ExpiryTimers` 내부에만 있다.

기존 TypeScript도 `Clock.schedule()`이 `CancelTimer` 함수를 반환하고 `SystemClock` 내부에서
`clearTimeout`을 처리한다. 이번 변경은 호출부가 취소 의도만 표현한다는 그 기준을 유지한다.
Java에서는 저장 대기가 있는 만료 작업과 실행기 종료 대기도 필요하므로, 두 실행기의 관리 책임을
타이머 모듈 안에 둔다.

## 테스트와 변경 과정

이번 작업은 **특성화 + 동작 보존 리팩터링**이다. 새 기능의 RED → GREEN 이력으로 포장하지 않는다.

1. 변경 전 타이머·세션·저장 테스트를 실행해 GREEN을 확인했다.
2. 이미 전달된 작업을 취소해도 중단하지 않는 동작과 종료 후 예약 거절을 특성화했다.
   두 테스트는 기존 구현에서도 통과했다.
3. 상속을 합성으로 바꾸고 호출부·fixture의 Future를 취소 핸들로 교체했다.
4. 종료 시 실행 중 작업 대기와 미래 예약 취소를 별개 테스트로 분리했다.
   `WaitingExpiry`가 시작·해제·완료 관찰과 실패 시 해제를 담당한다.
5. worker 대기를 임시로 제거한 변이로 종료 테스트의 검출력을 점검했다. 이는 새 기능 TDD의
   RED가 아니라 테스트가 회귀를 잡는지 확인하는 별도 점검이다.

종료 대기 테스트는 latch로 만료 본문을 붙잡은 상태에서 제한 시간 안에 close가 완료되는지 관찰한다.
이는 유한한 대기 구간의 관찰이며 모든 스케줄링의 수학적 증명은 아니다. 스레드의 WAITING 상태로
방 명령 큐 진입을 추정하지 않는다. 관찰값은 행동 단계에서 모으고 마지막에 검증한다.
미래 예약 테스트도 제한 시간 내 종료를 기다리며, 실패 시 종료 작업을 interrupt하여 자원을 정리한다.

근거는 `artifacts/migration-baseline/p3z-expiry-scheduling/`에 남긴다. 변경 전 소스, 기존 GREEN,
특성화 GREEN, 변이 검출 로그, 최종 Java·Spring 프로세스 E2E 결과와 diff/hash를 구별한다.
