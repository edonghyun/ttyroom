# 문서 안내

처음 실행하려면 [빠른 시작](../README.md)을, 설계를 검토하려면 아래 순서를 따른다.

1. [포트폴리오](PORTFOLIO.md): 해결하려는 문제, Spring 전환 이유와 선택의 비용.
2. [아키텍처](ARCHITECTURE.md): 프로세스 책임과 저장·확정·알림 순서.
3. [계약–코드–테스트](CONTRACTS.md): 설명을 실제 구현과 실패 테스트에서 확인하는 경로.
4. [검증 기록](VERIFICATION.md): 실행 환경, 테스트 범위와 미검증 범위.
5. [보안 모델](SECURITY_MODEL.md): 현재 신뢰 가정과 외부 서비스로 운영하기 전 필요한 작업.

개발할 때는 [개발 안내](DEVELOPMENT.md), [코드·테스트 가이드](CODE_STYLE.md),
[HTTP 계약](../protocol/HTTP.md), [WebSocket 규약](../protocol/PROTOCOL.md)을 참고한다.

날짜가 붙은 문서는 해당 시점의 변경·검증 기록이다. 과거 디렉터리명, 테스트 수와 미구현 항목은
그 시점의 상태를 설명하며 현재 실행 안내를 대체하지 않는다. `artifacts/`는 로컬 보관 자료다.
공개 저장소에는 원본 실행 로그·trace·임시 소스 복사본을 넣지 않는다.
GitHub Actions의 공개 실행 결과와 현재 테스트를 통해 별도로 재검증할 수 있다.

## 포트폴리오를 보완할 우선순위

| 우선순위     | 항목             | 완료를 판단할 근거                                                              |
| ------------ | ---------------- | ------------------------------------------------------------------------------- |
| 먼저         | 깨끗한 설치와 CI | 소스만 받은 환경에서 빌드·단위·통합·브라우저 검증 통과                          |
| 먼저         | 짧은 시연        | 두 브라우저의 제어권 전환·실제 출력·재접속 복구를 1~2분 영상으로 설명           |
| 먼저         | 대표 설계 설명   | 문제·선택·대안·비용을 코드와 테스트로 연결하고 면접에서 설명                    |
| 다음         | 인증 경계 완성   | 내부 credential 모델을 저장·등록 API·입장·취소에 연결한 E2E                     |
| 다음         | 측정 가능한 성능 | 환경과 부하 조건을 고정한 지연·메모리 측정. Node 대비 우위를 미리 주장하지 않음 |
| 선택         | API 문서 UI      | 현재 HTTP·WebSocket 명세 유지 비용을 확인한 뒤 OpenAPI나 문서 사이트 도입       |
| 공개 시 결정 | 라이선스         | 저장소 소유자가 배포 조건을 선택하고 의존성·참고 자료의 출처를 확인             |

현재 credential 모델은 입장 경로에 연결되지 않았으며 공개 저장소와 공개 서비스 운영은 별개다.
테스트 통과나 프레임워크 전환을 운영 성과로 표현하지 않는다.
