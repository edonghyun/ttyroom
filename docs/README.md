# 문서 안내

처음 실행하려면 [빠른 시작](../README.md)을, 설계를 검토하려면 아래 순서를 따른다.

1. [포트폴리오](PORTFOLIO.md): 협업에서 해결한 문제, 구현 범위와 설계 선택의 비용.
2. [아키텍처](ARCHITECTURE.md): 프로세스 책임과 저장·확정·알림 순서.
3. [계약–코드–테스트](CONTRACTS.md): 설명을 실제 구현과 실패 테스트에서 확인하는 경로.
4. [검증 기록](VERIFICATION.md): 실행 환경, 테스트 범위와 미검증 범위.
5. [보안 모델](SECURITY_MODEL.md): 현재 신뢰 가정과 외부 서비스로 운영하기 전 필요한 작업.

개발할 때는 [개발 안내](DEVELOPMENT.md), [코드·테스트 가이드](CODE_STYLE.md),
[HTTP 계약](../protocol/HTTP.md), [WebSocket 규약](../protocol/PROTOCOL.md)을 참고한다.

진행할 작업은 [포트폴리오 스프린트](../sprints/portfolio-readiness/README.md)에 등록한다.

## 포트폴리오를 보완할 우선순위

| 우선순위      | 항목             | 완료를 판단할 근거                                                    |
| ------------- | ---------------- | --------------------------------------------------------------------- |
| Sprint 1 완료 | 깨끗한 설치와 CI | 소스만 받은 환경에서 빌드·단위·통합·브라우저 검증 통과                |
| Sprint 1 완료 | 짧은 시연        | 두 브라우저의 제어권 전환·실제 출력·재접속 복구를 1~2분 영상으로 설명 |
| Sprint 1 완료 | 대표 설계 설명   | 문제·선택·대안·비용을 코드와 테스트로 연결하고 면접에서 설명          |
| 완료          | 인증 경계 완성   | 내부 credential 모델을 저장·등록 API·입장·취소에 연결한 E2E           |
| 다음          | 측정 가능한 성능 | 환경과 부하 조건을 고정한 지연·메모리 측정과 원시 결과                |
| 검토 완료     | API 문서 UI      | OpenAPI 응답 검증 채택; 별도 문서 UI는 탐색 필요가 확인될 때 재검토   |
| 공개 시 결정  | 라이선스         | 저장소 소유자가 배포 조건을 선택하고 의존성·참고 자료의 출처를 확인   |

credential 저장·등록과 [v8 입장](../protocol/AUTHENTICATION_V8.md), React·Connector 연동을 구현했다.
기본값은 v8이며 HTTP 취소·활성 연결 정리와 E2E까지 구현했다.
[HTTP 명세 자동 검증과 UI 선택](../protocol/HTTP.md#검증과-명세-유지)을 정리했다. 공개 저장소와 공개 서비스 운영은 별개다.
테스트 결과는 기록한 환경·조건에서의 동작 근거로 사용한다.

## 개발 이력

완료한 작업은 [WORK_LOG](WORK_LOG.md)에 주제별로 모았다. 변경 이유·검증 성격과
고정 커밋의 상세 원문을 함께 찾을 수 있다. 날짜별 작업 파일은 추가하지 않는다.

현재 계약을 바꾸면 해당 설계 문서를 갱신하고, 실행 결과는 [VERIFICATION](VERIFICATION.md),
남은 작업은 GitHub issue와 sprint에 반영한다. [인증 설계](AUTHENTICATION.md)는
작업 일지가 아닌 현재 설계·구현 범위 문서로 관리한다.

현재 기본 서버는 Spring Boot이며 `legacy/node-server`는 프로토콜 회귀 비교용 참조 구현이다.
예전 기록의 Agent는 현재 Connector에 해당한다. 프로토콜의 host·hostId는 연결된 컴퓨터를 뜻한다.
